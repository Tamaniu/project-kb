## PUBLISHING
### PUBLISHING OVERVIEW
##### Plan View
Publishing dashboards commonly track via the Plan view all the output for the platforms that you manage with the left menu display the stories of the day out of which you can plan your publishing simply by dragging and dropping into one of the publishing platforms.
Publishing point filters allow you to create these views.
You can sort a column manually (to sort them by priority or your defined order).
You can sort a column by time. To sort them by each publishing point start time.
Shows with a fixed time can be sorted manually regardless of the sorting option.
You can also set up the filter to include a specific folder, a specific status etc.
##### Story Publishing List
Inside of each story, In the publishing tab you can see, edit, and add publishing points for your story or production.
The publishing tab will display all associated publishing points for your story or production.
In the tab it will also display the total amount of pub points at the top, like we do for bookings.
On the Right menu you can also check the publishing plan for your story for the today:
##### Create
To add a new one simply click on the + button and select a folder and select a date and time for it
The publishing point will take the name of your story or production by default, to rename it click on the icon of the publishing point
You can also just open it by click on its title and in the window click on the title again to edit the title:
Creating a Publishing point is also possible from the Plan view
You can drag a story tile, or an episode tile for long form, from the left menu into a publishing column to create a publishing point for that publishing folder.
If multiple options are available in that column, you will have a popup window to select it after dragging it.
Note: If the Pub point column has a status filter, it will tag it with the column's status. If you try to drop it on a status beyond a step that requires approval it will error out to make sure you don´t sidetrack the workflow template.
##### Description and Additional Information
The first field you will find is the description field that can be mapped to the story description or the previous publishing point to automatically populate it. (See admin section)

Your template may already map some information from your story to your publishing point automatically. Like the title below. To do more editing, click on any of the fields.

##### Publishing Workflow
A publishing point will go through a publishing workflow to determine the steps and approvals required to publish to a platform
You can check this in the publishing point list, and it will display in all the plan views for tracking. Clicking on it allows you to change it and see when it was created and last modified

##### Bookings
You can add contacts for reference to a publishing point. This is not a booking, and they will not be notified of it, but it can be useful to know which specialist is part of your publishing point
You can also book guests to the publishing point which will allow you to track if they are coming into the building and the history of relationships for that guest with the organization across stories (see the resourcing workflow for more info on this).
You can book team members to collaborate on a publishing point if it is specific to its delivery and separate from the story or production
Finally, you can request people, equipment etc. for your publishing point
Note - see admin section because you can define to automatically assign the publishing point ownership to the first staff booking that you make.

1- Choose to add a workflow step and select it from the list of existing workflow steps or add a new one.

4- Add Notifications (Optional) if a resource type needs to be notified when a publishing point change to this new workflow step this can be done here (on start and on completion)
5- Decide which workflow step is the one that will publish it to the 3rd party system. Note, once it is published it will go to the next workflow step and will be locked.

##### Migration to new folder structure
When you transition to the new plan view you will not need to recreate the existing publishing points. Wolftech will work with you to migrate existing publishing points to the new folder structure.
In the Admin-Platform page, within the slots conversion tab, you can connect each of your existing publishing slots to a publishing folder. The rule that applies is that you can connect a publishing slot to only one publishing folder (i.e., the same publishing slot cannot be mapped to multiple publishing folders). However, you can map multiple existing slots to the same publishing folder if needed).
To do so click on the slots conversion tab, then choose your sub platform or platform (wherever you are managing publishing points) and you will see all the slots that currently exist within it. Click on the one you want to connect and choose the publishing point folder to the right you would like to connect it to before clicking on the connect button.
For compatibility purposes, you can connect Generic Sub Platform or Open Media Sub Platforms to publishing folders that were created from another platform provided that
They have the same Platform Type (i.e., part of generic platform or Open Media)
They use the same Publishing Package Template
They have the same Publishing Workflow Template
This allows to consolidate and merge teams that may have been previously grouped in different platforms but with the same workflow
Do note that for iNews compatibility factors the connected publishing folder needs to have been created out of a sub platform from the same platform as the original slot (i.e., in the image above the publishing folders have all been created from sub platforms within the 24-7 News Channel 6 platform.)
To make the publishing points visible in the new plan view you will need to connect all the slots from the sub platform and click on the “add to new plan view” button. This guarantees that the process is handled in a secure way that will not affect your system´s activity.
If there are any slots you no longer require, we recommend you delete them or if legacy just map them to a publishing folder, since if there may be no publishing points to worry about the final process will just take care of the deletion itself.
Once added, publishing points from the last 2 weeks and into the future will be at this point active in both the old and new plan view in parallel. In the old plan view the slots will continue to work. In the new plan view those same publishing points will display in the connected folders. We do not recommend extending for too long this parallel status for performance reasons.
If you need to disconnect a slot to connect it to another publishing folder you can just click on the undo button that will be available after “adding to new plan view,” then choose a slot to reveal the connected publishing folder and disconnect it. You will need to connect to another folder before you can choose the “add to new plan view” again.
Once you are ready to migrate your teams you will need to convert the slots to fully migrate all publishing points to the new publishing folder. This process cannot be undone and requires careful execution as once you convert the slots they will be deleted, and all publishing points will only display under the new publishing folders in the new plan view. At this point all historical publishing points (prior to the 2 weeks window initially handled) will be fully migrated to the new folders
To run the conversion, click on the “convert slots” button.
In summary the process will be:
Admins first set up the folder structure required.
Admins set up your plan views leveraging those folders to be fully sure the folder architecture works for your organization (see PLAN view documentation for help with that).
Admins connect Old Slots to the new publishing folder structure
Admins add all the connected slots for a sub platform to the new plan view to monitor publishing in the new plan view
Admins review the setup with super users to verify it is working as expected
Once approved, Admins grant access to new plan views to the full team and convert the platform/sub platform slots to finalize migration for that team.
Admins work with the next team until all the old plan view items have been migrated.
Admins switch the “use new plan view” admin option to force all users into new plan view
***PLEASE NOTE that the new Plan view and new folder structure is NOT supported with the current mobile (V3) application and will only be supported by the new Mobile App (V4). The new mobile app will be available at the same time as R11, and it will support both new and old plan views to make this transition easier.
Also note you can have users in the old plan view and users in the new plan view, however users in the old plan view will not be able to see publishing points created in the new structure in the new plan view. Users in the new plan view could admittedly switch to the old plan view if they want to see publishing points organized in the old structure. As such we recommend migrating whole teams together for efficiency.

Using Live Feeds for Live Blogs
All relevant endpoints are described in the Live Feed and Live Feed Message sections of the API docs: https://localdomain/api/doc (https://news.wolftech.no/api/docs/)
General flow
A new Live Feed is created via the API
Once at least one Live Feed has been created, the Live Feeds view collection can be found as a shared view collection in the Feeds page
The Live Feeds view collection contains only one view
All created Live Feeds will be shown as columns in the Live Feed View
The Live Feed View and Live Feed View Columns cannot be modified, copied, or changed from the Wolftech UI or Admin page
If users want to quickly access Live Feeds without loading the Live Feeds View Collection, they can Favorite the Live Feed View page
Once a Live Feed exists, messages can be posted to it
A Live Feed message is very simple, it contains a title, a body, an author name, and a timestamp
A Live Feed will expire a certain amount of time after the last message was posted to it, when it expires its column is deleted from the Live Feed View
If the Live Feed View is open in the Feeds page, new columns will automatically show up once they are created, and expired columns will be removed
Clicking on a Live Feed message will open it in a simple modal to see the full message

##### Rundown: iNEWS
iNEWS is integrated so you can push stories from Wofltech to iNEWS and get the updates to the connected iNEWS stories back to Wolftech.
Be aware that Wolftech uses the CTMS API to connect to iNEWS and at the moment it will need to lock the story to edit it in Wolftech. This will make the iNEWS story locked and it won´t be able to tell iNEWS who is locking this story.
We will keep you posted with our exciting roadmap for deep integrations with iNEWS.
To set up a connection to an iNEWS first make sure to have the setup in Workflow Engine with the help of our support team.
Then configure the server connection in the platform level
You will then be able to map rundowns from that server to sub platforms under that platform
To make sure you have templates to use, go to the templates area
Create a new template
Import an iNEWS nsml file which will load a list of preconfigured fields.
Click on Add All to add all of the fields to the wolftech template.
You will then be able to map the template to the sub platform
Once the setup is complete and you have a publishing folder connected to the sub platform you will be able to begin publishing to iNEWS.
##### Rundown: Open Media
From Wolftech you can push stories to Open Media mapping valuable production metadata along the way. The integration is 1 way. Once the story is created in Open Media it is no longer updated back from Open Media to Wolftech.
To configure the connection please contact our workflow engine specialist.
##### Podcast: Acast
To publish your audio content to multiple podcast destinations Acast is the perfect partner as it can then syndicate to 3rd party platforms like Apple Podcasts, Google Podcasts, Spotify, Amazon Music, Samsung Free, and hundreds of others.
Mapped fields:
ShowID (hidden) - Created by admin in WT template
Show Title (non-editable) - Part of template, related to ShowID
Title - Episode title
Subtitle - Episode subheading
Audio file - Mp3 or m4a (Drag media from board or directly upload to field)
Status - Draft/published/scheduled.
Summary - Description of episode
Link - Optional website link for episode
PublishDate - Date and time for scheduled publishing
Episode type - Full/trailer/bonus
Explicit content - True/false
Cover - Episode cover (jpg/png). (Drag Media from board or directly upload to field)
Status message from Acast API - “Upload completed,” “upload failure,” etc.
The status can be changed between draft, published, or scheduled. This can help you track the status internally. To be able to fully publish it make sure this is marked as Published before publishing.
Note Acast does not support analytics, so we do not get that data back.
The Acast icon is now added to options in sub platform technical configuration and in publishing hierarchy folder
