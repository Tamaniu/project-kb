## PUBLISHING
### PUBLISHING OVERVIEW
##### Plan View
Publishing dashboards commonly track via the Plan view all the output for the platforms that you manage with the left menu display the stories of the day out of which you can plan your publishing simply by dragging and dropping into one of the publishing platforms.
Publishing point filters allow you to create these views.
You can sort a column manually (to sort them by priority or your defined order).
You can sort a column by time. To sort them by each publishing point start time.
Shows with a fixed time can be sorted manually regardless of the sorting option.
You can also set up the filter to include a specific folder, a specific status etc.
##### Story Publishing List
Inside of each story, In the publishing tab you can see, edit, and add publishing points for your story or production.
The publishing tab will display all associated publishing points for your story or production.
In the tab it will also display the total amount of pub points at the top, like we do for bookings.
##### Story Publishing Schedule
On the Right menu you can also check the publishing plan for your story for the today:
##### Create
To add a new one simply click on the + button and select a folder and select a date and time for it
The publishing point will take the name of your story or production by default, to rename it click on the icon of the publishing point
You can also just open it by click on its title and in the window click on the title again to edit the title:
Creating a Publishing point is also possible from the Plan view
You can drag a story tile, or an episode tile for long form, from the left menu into a publishing column to create a publishing point for that publishing folder.
If multiple options are available in that column, you will have a popup window to select it after dragging it.
Note: If the Pub point column has a status filter, it will tag it with the column's status. If you try to drop it on a status beyond a step that requires approval it will error out to make sure you don´t sidetrack the workflow template.
### PUBLISHING EDITOR
##### User Experience and Navigation
The publishing editor has several sections that is important to familiarize yourself with.
On the left you can see a number of icons representing the publishing point list for the story you are in. Clicking on those items will open each output so you can edit them. At the top of the publishing point list you will find the story icon. You can click on it to navigate to the story.
On top of the story icon, you will find an arrow to expand the publishing point list and see more information:
The system will remember your last used settings so next time you open a publishing point it will have the publishing point list collapsed or expanded depending on it.
In the center top you will find the publishing point Header. Here you can see
- the Publishing Point title (editable if you click on it)
- The publishing point unique iD (That can be copied)
- The status of the publishing point, that can be adjusted
- The ability to follow the content
- A 3-dot menu for further actions
- Below you will find the schedule of the publishing point (i.e. when and where it will be published).
As you scroll down the header will become sticky and will show less information
In the center middle section below the header, you will find the publishing tabs
- The editor tab – to edit the content and publish the content
- The details tab – where you can add a description, additional information and manage guidance requests.
- The bookings tab – where you can book or request resources to deliver the publishing point.
- A notes tab to add a long list of notes.
In the editor tab you will find the editor itself which is broken into 2 sections.
- A Form Panel on the left (which can be collapsed and hidden by default)
- a content (Script Editor) on the right
The fields and actions of these subpanels depend on the type of publishing you are working on.
On the right section you will see the Right Panel. This includes
- A message thread to discuss and collaborate on all aspects of publishing
- An activity log – to check on all the activity updates for this publishing point
- A Board – to select media to be published
The right panel can be collapsed and opened by clicking on the icons on the right. The X button closes the whole publishing modal.

To begin, unlock the editor and choose a template if need be.
After that you will be able to enter the details of your publishing point by simply clicking on any of the fields on the center panel
Your template may already map some information from your story to your publishing point automatically. Like the title below. To do more editing, click on any of the fields.

Changing Templates and Mapping
If you need to change the publishing point template of an existing publishing point you can do so without losing its data (mapping the data to the new chosen template) If you have a publishing point where you have already worked on adding the metadata:
When you change the template (see FB Video Post) you will be presented with an option to start the new publishing point from scratch or convert the data to match the new template
All fields where there is a matching field title will be mapped automatically but you will have a chance to manually adjust mapping as needed for those where there is no match
Publishing Workflow
A publishing point will go through a publishing workflow to determine the steps and approvals required to publish to a platform
You can check this in the publishing point list, and it will display in all the plan views for tracking. Clicking on it allows you to change it and see when it was created and last modified
You can adjust the status in the top right with the drop down or by clicking the next button.
If an approval is required in the workflow template, you will either not be able to move it beyond its status or see an approve button:
Clicking on the approve will move it to the next stage
Once you reach a stage where the next action is to publish, you will see the publish button to the left of the status.
Note, after this point the publishing metadata and content will be published to the 3rd party platform and the status of the publishing point will move to the next stage.
Failure or success of publication will come in a notification

##### Bookings
You can add contacts for reference to a publishing point. This is not a booking, and they will not be notified of it, but it can be useful to know which specialist is part of your publishing point
You can also book guests to the publishing point which will allow you to track if they are coming into the building and the history of relationships for that guest with the organization across stories (see the resourcing workflow for more info on this).
You can book team members to collaborate on a publishing point if it is specific to its delivery and separate from the story or production
Finally, you can request people, equipment etc. for your publishing point
Note - see admin section because you can define to automatically assign the publishing point ownership to the first staff booking that you make.
##### Notes

The notes field now has a character count to let you know when you are about to reach the 4000-character limit and will prevent you from trying to continue to write beyond its maximum capacity. Chat

This right panel can be dragged to be wider to make the best use of it:
Activity Log
The publishing point´s activity log tracks the editorial activity inside of a pub point.
This includes status changes, description changes, additional information changes, changes to the template editor (content) and comments. Note: It does not include Publishing point title  changes.
Users can choose when to notify of changes to the additional information fields by clicking on the log activity. This will give you a message that the activity has been successfully logged and those that click on the log will be directed to see the changes:
Users will also be able to manually log activity changes to the template in the editor with the same Log Activity button. This appears when you unlock the template for editing.
Note, in this instance you can make multiple changes to the template, and we will just notify you that the template has been updated.
In the description field, like on the editorial segments, saving the change will update the activity log but you can also save without logging for correction on typos:
Follow, Notifications and the Activity Feed
The owner of the publishing point or those booked on it will be notified of changes to its status.
Other team members can follow a publishing point to receive updates with any editorial changes to it.
This includes changes to, updates from the additional information section, changes to the publishing template, comments, or changes in status.
The activity will be presented in the activity Feed. See the Communication and collaboration guide for more information.
To change the notification preferences for publishing point changes, go to your My Page - Notifications menu:
Read and Activity Updated Indicators in Pub points
To help you navigate the increasing amount of content output and focus on what matters, when you are planning your publishing calendar, we will give you 2 indicators to check
New Publishing points you have never accessed (Unread) - Orange dot
Publishing points that have been updated since the last time you accessed them - orange triangle
With the orange triangle on hover over you will be able to see the last change and from there you can click to dismiss the update on the triangle or click on the publishing point to see the full activity log

Sharing a Publishing point
If you need to share the details of the pub point you can do so in multiple ways.

Alternatively, you may want to share the Publishing Point Unique ID. This can be found on the pub point under the title and can be copied and may be helpful if you need to find this ID in a 3rd party system.

Printing

For each Platform type you can create Publishing Platforms.

The most important aspect here is “Default workflow template”. This defines the steps required to successfully publish to this platform (like “to do”, “in progress”, “packaging”, “ready to publish”, “published”) We can explore this separately in this guide.
Workflow templates
They can be setup in the admin - templates section
Inside you will be able to manage the template
1- Choose to add a workflow step and select it from the list of existing workflow steps or add a new one.
2- Define if the workflow has a previous dependency. Ie you cannot move to this workflow step until a previous one is completed
3- Setup Approvals (Optional). If an approval is set up, you will indicate that someone with the given resource type that has been booked in the story will be able to approve this step.
4- Add Notifications (Optional) if a resource type needs to be notified when a publishing point change to this new workflow step this can be done here (on start and on completion)
5- Decide which workflow step is the one that will publish it to the 3rd party system. Note, once it is published it will go to the next workflow step and will be locked.

Publishing Template(s)
Are the collection of fields that format how your story is published to a 3rd party system. The template lists out the information that should be gathered in the format and structure needed for publishing. For example, some social platforms may have certain character limits to hit and require specific ancillary data.
To edit a publishing package template, navigate to the admin-publishing section. Go to the templates tab and choose one platform from the left menu. This will show you the templates available for that given platform type:
Templates can be grouped in template groups if many exists.
Once you click on a template you can see the fields that is made out of.
Generic fields vs Template Fields and getting help
On the right you will see Template fields vs Generic Fields.
Generic Fields will NOT be pushed to the 3rd party system.
For the fields to connect with external platforms they need to be configured in the template.
Overall Generic Fields have become a legacy since the introduction of additional information fields and would recommend having any logistical information that does not need to be published to a 3rd party system in the additional information section. That way the editor template is understood to be what will be published.
Whilst Publishing templates can be configured manually, they should always be discussed with your project manager if you would like to use them to publish to 3rd party to make sure the workflow engine, who is pushing the data to your 3rd party platform, is configured correctly.

Using Live Feeds for Live Blogs
All relevant endpoints are described in the Live Feed and Live Feed Message sections of the API docs: https://localdomain/api/doc (https://news.wolftech.no/api/docs/)
General flow
A new Live Feed is created via the API
Once at least one Live Feed has been created, the Live Feeds view collection can be found as a shared view collection in the Feeds page
The Live Feeds view collection contains only one view
All created Live Feeds will be shown as columns in the Live Feed View
The Live Feed View and Live Feed View Columns cannot be modified, copied, or changed from the Wolftech UI or Admin page
If users want to quickly access Live Feeds without loading the Live Feeds View Collection, they can Favorite the Live Feed View page
Once a Live Feed exists, messages can be posted to it
A Live Feed message is very simple, it contains a title, a body, an author name, and a timestamp
A Live Feed will expire a certain amount of time after the last message was posted to it, when it expires its column is deleted from the Live Feed View
If the Live Feed View is open in the Feeds page, new columns will automatically show up once they are created, and expired columns will be removed
Clicking on a Live Feed message will open it in a simple modal to see the full message
Examples
Creating a Live Feed
Request URL: https://news.wolftech.no/api/v2/command/live-feed/create

Status Code: 200 OK

##### Rundown: iNEWS
iNEWS is integrated so you can push stories from Wofltech to iNEWS and get the updates to the connected iNEWS stories back to Wolftech.
Be aware that Wolftech uses the CTMS API to connect to iNEWS and at the moment it will need to lock the story to edit it in Wolftech. This will make the iNEWS story locked and it won´t be able to tell iNEWS who is locking this story.
We will keep you posted with our exciting roadmap for deep integrations with iNEWS.
To set up a connection to an iNEWS first make sure to have the setup in Workflow Engine with the help of our support team.
Then configure the server connection in the platform level
You will then be able to map rundowns from that server to sub platforms under that platform
To make sure you have templates to use, go to the templates area
Create a new template
Import an iNEWS nsml file which will load a list of preconfigured fields.
Click on Add All to add all of the fields to the wolftech template.
You will then be able to map the template to the sub platform
Once the setup is complete and you have a publishing folder connected to the sub platform you will be able to begin publishing to iNEWS.
##### Rundown: Open Media
From Wolftech you can push stories to Open Media mapping valuable production metadata along the way. The integration is 1 way. Once the story is created in Open Media it is no longer updated back from Open Media to Wolftech.
To configure the connection please contact our workflow engine specialist.
##### Podcast: Acast
To publish your audio content to multiple podcast destinations Acast is the perfect partner as it can then syndicate to 3rd party platforms like Apple Podcasts, Google Podcasts, Spotify, Amazon Music, Samsung Free, and hundreds of others.
