## LONG FORM PRODUCT OVERVIEW:
### INTRO
The Long Form Module is a Wolftech Add-On that enables a number of functionalities to help teams manage long form productions within their existing Wolftech News story planning product.
This guide aims to introduce the Long Form Module in detail.
It is aimed at admins but It will cover both administrative duties as well as general functionality so admins and super users feel confident training teams internally.

__________________________________________________________
### ACCESS - USER TYPES
The long form module is an add-on that is activated at the account level. Everyone who gets access to Wolftech News as part of the account will therefore be able to leverage the long form module. The same SSO and authorisation protocol works. No changes required.
For further details on user management see the admin guide.
The application can be accessed either through your browser at your own company defined url or via the mobile app.
Typically the web interface is used by managers, coordinators, planners, and editors and the mobile app becomes the primary interface for journalists, reporters, producers in the field and related crew.

### CONTENT ORGANISATIONAL LEVELS
Whilst the long form module allows you to plan projects that require an episodic type of organisation, content across Wolftech, no matter whether long form or story based, is organised under departments or brands, depending on your organization´s setup.
####### Organisational Levels
An Admin will manage this within the admin - organisational levels section where they can set all types of content access permissions and define where content vs shows can actually live.

Typically you may have a department-brand top level that may have subdepartments-brands living under them and within them you will have Franchises or shows. Because the hierarchy can be different per customer we have made it very flexible for you to define where shows actually live.
####### Shows
Shows are treated as their own brand-department but automatically get certain permissions, like the ability to greenlight content within them:

Shows are different from departments or brands in that they enable you to create seasons within them.
For further flexibility Shows can be reorganised into different departments-brands by dragging them to the new department level on the list on the left.
To create a new show you can do it within the Quick Add menu (Orange + icon)
1- + Button
2- Select to add Production
3- Choose to add a show
4- Select in which department or brand you want the show to created in
5- Give the show a title and a description
6- Click to add

####### Seasons & Episodes
Within each show you may have multiple seasons that in turn contain multiple episodes each.
To create a season use the quick add again. It is the same process only this time you get to choose a show where the season should live instead of a department

Seasons can be named manually and are the key identificator on Episode cards so we recommend naming them “Show Name S#” for easy identification although again, for flexibility, we have left this open so you can organise it in whichever works best for your team.

When creating a season you can define the number of episodes that season may contain so all episodes are created together with the season.
As such you can also define the Production Type (Formats) for the episodes (more on this later, it can be changed after creation)
At this point you can also select to have the same project template for all of the episodes and tag them with a genre if you want to.

### PROJECT KICK OFF

We understand that the project kick off is never a one size fit all approach. Sometimes you may have a structured pitch presentation and review process with a development phase and other times you need to go straight into a quick greenlight process to catch the action.

####### Pitch vs Production start

In wolftech you have 2 ways of kicking off your projects as a result: Pitch or Production which effectively would work in this order:
Pitch (Development info)-> Creative Review: Discard or Convert to Production-> Budget/Schedule review: Discard or Greenlight
Production (Dev and Budget/Schedule info) -> Full Review: Discard or Greenlight
The length that may take from project conception to greenlight may vary per team and project but the structure should follow one of these 2 models.
The main differences at the start are:
If you start with a pitch you can create them at any department level (CBS News) rather than with productions where they need to live at the show/season level. (60 Minutes - 2024)
If you start with a pitch you will be able to automatically see similar stories other teams are working one before you start
If you start with a pitch you will be able to make the project private, or have a different permission level for development, to begin with while you and close colleagues work on it until it is ready to share widely.
If you start with a pitch you don't need to choose a project template yet (as you don´t know yet how you plan to schedule the project)
With Pitches you have the option to give them some dates (after which point they are no longer relevant and they simply disappear or make them timeless (evergreen), so they are always there unless discarded. Productions slightly different in that until you give some dates to the schedule they will be automatically considered timeless (evergreen).
Once the project is greenlit you may be able to track and manage your project.

Wolftech simplifies all of the related project setup tasks by asking you to provide the information just once, so all team members can find it there (rather than provide this information each time you deal with one assignment). It will also allow you to have a dedicated communication channel from the beginning, as well as to create a Media Collection in your MAM if integrated to have all of your required team fully connected in one place. Finally wolftech will automatically generate a kick off email including everyone in your booking or key resources list

Note: You can create a production out of a feed
This will keep the title, description and add the feed to the board

But you cannot create a production out of an event

And you cannot create a production out of a story at this moment in time.

You can however link stories, or events or logs to a production after the fact by dragging from the hunter.

### TEMPLATES
Templates are at the heart of the long form module. They allow you to define and automate many aspects of your production to make sure you get off to a great start.
When creating a production (or when converting a pitch to a production) you will be able to select a project template. These are detailed building blocks for your project schedule including
the right phases and tasks
their dependencies
their duration
the roles that are meant to perform those tasks as well as
approvals and notifications
This can also guarantee the teams are following best practices and are not making risky schedule decisions because they lack visibility of onward processes that may depend on them.
When creating a new project it is generally not advised to use the “same as” feature as it will allow you to copy the phases and tasks of an existing production but it won't allow you to use the same logic for the resourcing, notifications and approvals.
Some examples of potential templates for episodic content could include:
Social First
Digital Short Form
Studio based Shows
Sports
Investigative short form
Long form
Feature Film
Audio Podcast
Branded campaign
A schedule that started with a template can later be edited by adding or removing tasks, changing the dates, etc., it is only meant as a quick start to get teams into the right framework.
A template can be swapped with another template after project creation though it will unconfirm all of the existing bookings to get you a fresh start so be mindful of that.
To create or edit a template you will need to have the right permissions.
See the admin Section of the guide for more information on how to create and edit these templates.

####### Edit the Schedule
Once you have the right start to your project you are ready to edit the schedule.
On the top right you have some controls:

Editing the schedule follows the following logic:
First work at the phase top level. Drag a phase to a new start date and it will move all of the tasks within that phase in the same order.

### RESOURCING
When it comes to people or equipment bookings it is important to differentiate approaches for:
those teams that are managing their productions fully in wolftech
those who are just using it to access shared calendars for resourcing (AEs/Finishing/Suites) but are not yet fully in wolftech. If you are in the latter group you can skip to this section.
Also, when you want to book someone or something for a task you may manage those resources yourself, so you can do the assignments, or you may need to request it from another team, so they take care of your request and manage the assignment for you. Let's start with how you can request equipment or people from other teams.
##### Requests
To request equipment or people from other teams navigate to the correct task in your project´s timeline (Prod- Shoot for a drive or a Camera Operator or Edit - Offline for an edit suite or an editor for example).

Within the task you will see a + button. This will give you a dropdown where you can navigate to the type of equipment/people you need (Ie. Media - Hard Drive or Post - Facilities/Equipment, or Prod - Photography for Camera Operators, DoPs, etc.).

Once you have selected the type of Equipment/People you will be presented with the Full Booking page where you may select a sub category if it applies (10TB drive vs a 2TB..)
Select the dates you need the equipment/people for.
At the bottom there may also be some questions that require answers from the teams managing those types of resources (a contact email, types of cables, etc.) Any mandatory information will be marked with a red dot.
Be sure to add any preferred people or pieces of equipment in the notes field.
Once you have it completed you may want to tag someone in the message thread so they are notified of this request. This could be a distro list or someone in particular.

Once you are happy with your request just click on Send request.
This will reach the intake tray of those managing the people/equipment requested and will notify anyone tagged on the message thread.

*ProTip: You can use the request function to plan resources you know you are going to need in the future but don’t want to request them yet. If you click on the request function, find the resource you need but instead of sending the request you click on save it will store the type of resource you want, and the data for dates, etc you have filled so far but it wont send the request yet, so you are able to send it later. This can be useful when you want to clarify what resources will be needed for a project in a development phase to plan your options ahead of either requesting them or assigning them to anyone.

##### Managing Requests

####### Templates: Creating or Editing Production Templates
In the admin - templates section you will be able to create a new template or open an existing one to adjust it

If you select to open one you can select the template you want to edit. Otherwise you will begin with a blank start.

Stages
Template stages follow a hierarchical structure
Phases: These are the overarching phases of your project
Tasks: These are the tasks that need to be completed in each phase
Milestones: These are key moments for each phase and may also contain tasks within them if need be.
Each stage can have a dependency on another

Creating a new phase, task or milestone is easy with the buttons at the top of the template editor. Then select the existing stage from the right
If the name for your phase does not exist yet, navigate to the bottom of the list ot create a new stage name:

If you need to create an element underneath an existing stage simply click on the 3 dot menu next to the stage:

Once added you can add a description to the stage so it is visible when opened by the team members. This can be particularly useful to add expected subtasks or elements in that task so as to keep the templates simple.

As you can see, adding or editing existing stages is easy! However there is no option to delete a stage from the drop down list. Because of this it is important to keep a very organised list of stages that are later easily searchable. We recommend admins to try to steer this into a good naming convention.

Duration
For each stage you can define the expected duration. For phases this does not need to be equal to the duration of the tasks inside of it, allowing you to create buffer days in between phases.
You can also define whether to include weekends in your duration count.
Optional Stages
Tasks can be marked optional. This means that a decision must be made whether to include them or not in an episode before greenlight. Examples of this can be items like Translations, or Custom Graphics.

Assignments
In the assignments section you can define the resource types that sould perform the tasks and also mark if a specific resource type may need to approve a task or stage

Select one or multiples and this will create booking placeholders that can then be assigned in bulk. Ie, if a producer is in charge of the shoot, a pre production meeting and the paper edit tasks, you will then be able to assign a producer and automatically propagate his assignment to all 3 tasks.
Note that you can add placeholder bookings for not only people but also equipment or teams:

On the approval side if more than one resource type can approve, any of the resource types can approve the task, not all of them are required to approve it.
Alerts & Notifications
Add alerts for delays or overdue stages by defining which resource types (roles) in the project should be notified of them.
Add notifications for stages starting, completing or changing dates to make sure the right people can be kept in the loop of important schedule changes or dependent task handovers can happen swiftly in a production.
Once a template is created users will only need to select it in the quick add or in the timeline and add a start date, or end date to make sure you can deliver by x date, to automatically build a full schedule with correct timeline, dependencies, assignments, notifications, and approvals in one click.
It is advisable to test your newly created template to make sure you have got the correct dependencies dates, etc. assigned before communicating this to your teams.
Overall templates are a great way to make sure teams follow best practices and are not making risky schedule decisions because they lack visibility of onward processes that may depend on them.
